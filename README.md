# Musiienko_nosql_1: Аналітична платформа для стрімінгового сервісу

## Налаштування оточення
1. Встановіть залежності: `pip install -r requirements.txt`
2. Створіть файл `.env` у корені проєкту та додайте свій URI:
   `MONGO_URI=mongodb+srv://user:password@cluster.mongodb.net/`
3. Запустіть скрипт імпорту: `python scripts/01_load_data.py`
4. Виконайте трансформацію схеми через Mongo Shell:
   `mongosh "ВАШ_URI" --file scripts/02_transform.js`

🔹 Частина 1 — Завантаження даних та проєктування схеми

1. Чому аудіо-характеристики винесені в окремий об’єкт audio_features, а не зберігаються плоско? Коли таке вкладення вигідне, а коли створює проблеми?

Це відповідає парадигмі NoSQL: групування пов'язаних даних. Це покращує читабельність та структурує документ. Вкладення вигідне, коли ми часто звертаємося до цих фіч як до єдиного цілого. Проблеми можуть виникнути, якщо вкладеність стає надто глибокою, що ускладнює індексацію та побудову багатошарових запитів.

2.Чому виконавці зберігаються як масив, а не як рядок? Які запити стають простішими?

Масив дозволяє базі даних створювати Multikey Indexes. Це робить пошук миттєвим за допомогою операторів $in або $all. Якби це був рядок, нам довелося б використовувати регулярні вирази, які викликають повільне повне сканування колекції (COLLSCAN).

3.Що таке $out і чим він відрізняється від $merge? Коли використовувати кожен?

$out повністю перезаписує вказану колекцію, видаляючи попередні дані (ідеально для повної ініціалізації бази). $merge дозволяє вставляти нові документи або оновлювати існуючі (ідеально для інкрементальних оновлень, наприклад, коли надходять нові треки).

🔹 Частина 2 — Запити до даних

1. Для чого використовується інструкція $unwind?

Вона денормалізує масив, створюючи окрему копію документа для кожного елемента масиву. Якщо трек має 3 виконавців, $unwind розщепить його на 3 документи. Це необхідно, щоб згрупувати ($group) статистику персонально по кожному виконавцю.

2. Чим $stdDevPop відрізняється від $stdDevSamp?

$stdDevPop (Population) використовується, коли ми маємо повний набір даних (генеральну сукупність) — у нашому випадку це весь датасет. $stdDevSamp (Sample) застосовується, коли ми аналізуємо лише вибірку (частину даних), і потрібно зробити статистичну оцінку з похибкою.

🔹 Частина 3 — Аналітика через Aggregation Pipeline

1. У запиті 1 ми фільтруємо виконавців, у яких менше 5 треків. Як зміниться результат, якщо знизити поріг до 1? А що станеться, якщо вибирати виконавців із більш ніж 50 треками? Поясніть результат.

Якщо знизити до 1, топ заповнять артисти-одноденки (з одним вірусним хітом), викрививши об'єктивність рейтингу. Якщо підняти до 50, ми відсіємо перспективних артистів і побачимо лише ветеранів індустрії з великими дискографіями.

2. У запиті 3 ми фільтруємо жанри з менше ніж 100 треками. Чи зміниться результат, якщо знизити поріг до 50? Поясніть результат.

Це знизить статистичну надійність. Жанр із 51 треком може випадково показати аномально високий середній показник через особливості вибірки. Що більший поріг, то згладженіший і достовірніший результат.

🔹 Частина 4 — Індекси та оптимізація

1. Що змінилося в плані виконання?

ДО індексу: winningPlan.stage був COLLSCAN, а totalDocsExamined дорівнював загальній кількості треків (близько 114 тисяч). База читала кожен документ, щоб перевірити умову.

ПІСЛЯ індексу: winningPlan.stage змінився на FETCH -> IXSCAN. totalDocsExamined впав лише до кількох тисяч документів, що підходять за умовою. Час виконання (executionTimeMillis) скоротився з десятків мілісекунд до ~1-2 мс. Індекс працює за правилом ESR.

2. Як зрозуміти, що індекс використовується? Наведіть скріншот або значення полів із explain(), які це підтверджують.

Запит: db.tracks.find({ track_genre: "pop", popularity: { $gte: 70 } });
Ні, він не покривний. Хоча поля track_genre та popularity є в індексі, метод .find() без додаткової проєкції повертає весь документ (разом із _id, виконавцями тощо). Оскільки цих полів немає в індексі, базі доводиться звертатися до пам'яті (стадія FETCH), щоб дістати повний документ. Щоб запит став покривним, треба додати проєкцію: ...find({...}, { _id: 0, track_genre: 1, popularity: 1 }).
